How it works

A folder is the agent. A policy is the leash.

Everything the agent is lives in plain files you can read and edit. Everything it does passes through one payment policy and one approvals inbox — whichever surface you're using.

You

  • Terminal: xdc-agent
  • Telegram bot
  • Dashboard
  • Routines (cron)
→

The agent

  • SOUL.md identity, AGENTS.md rules
  • MEMORY.md + daily logs + semantic recall
  • 58 skills, sandboxed run_command
  • Sub-agents: researcher, treasurer
  • Any LLM (see below)
→

Tools

  • XDC AI wallet + 100+ pay-per-call APIs
  • Slack, Gmail, Drive, Calendar, Notion, GitHub…
  • Isolated shell (Seatbelt / bwrap)
⚑ Payment policy + approvals: cheap calls run alone · above your threshold, every transfer, every write, every send → waits for you (terminal, Telegram or dashboard) · caps enforced in code, not by the model

Install

Three minutes on a Mac mini, a Linux box, or your laptop.

No Docker required. Needs git; Node and pnpm are installed for you if missing.

  1. Run the installer

    Clones to ~/xdc-ai-agent-starter-kit, pins Node, installs dependencies, puts xdc-agent on your PATH, then starts the setup wizard. 

    $ curl -fsSL https://raw.githubusercontent.com/0xbeny/xdc-ai-agent-starter-kit/main/scripts/install.sh | bash
  2. Answer the wizard

    Model & key (or Claude Code) → SQLite or Postgres → link your XDC AI wallet (a code you approve in any browser) → spending caps → connectors & Telegram. On macOS it offers to run at login.

  3. Talk to it

    New terminal, then:

    $ xdc-agent            # chat — type / for commands
$ xdc-agent dashboard  # start + open the UI (prints the ssh -L command over SSH)
$ xdc-agent telegram   # connect a bot, get the pairing code
$ xdc-agent update     # update the kit — your workspace, data and .env are never touched

Security defaults

Built to be trusted with a wallet.

Caps in code

Auto-approve threshold, per-call max and a daily cap are enforced before any paid call; the model can't talk its way past them.

Approvals everywhere

One inbox — dashboard, Telegram buttons or /approve in the terminal. Approvals are single-use and bound to the exact arguments.

Untrusted content stays data

Email, docs, channels and paid API results can never trigger a send or a payment without you.

Secrets stay local

.env and token files (0600) never leave the machine; vault references (op://, bws://) supported; logs are redacted.

Sandboxed execution

Commands run in a scratch dir with Seatbelt (macOS) or Bubblewrap (Linux), no network by default, destructive commands refused.

Updates can't touch you

Identity, memory, tokens, ledger and settings are outside git; xdc-agent update fast-forwards code only.
